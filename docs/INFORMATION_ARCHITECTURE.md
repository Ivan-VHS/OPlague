# OPlague documentation information architecture

[Project README](../README.md) · [Documentation index](README.md)

This is the canonical map for the OPlague documentation library. The full catalog is built from the current repository tree. Source, tests, schemas, release workflows and security rules remain authoritative for implementation and trust boundaries.

## Entry points and authority

- **Project entry:** [README](../README.md) — read-only workbench scope, setup and limitations.
- **Documentation home:** [docs/README.md](README.md) — key references and topic hubs.
- **Feature matrix:** [FEATURES](FEATURES.md) — capability boundaries and maturity.
- **Security policy:** [SECURITY](../SECURITY.md) — local static scanner and disclosure process.
- **Authority:** source and tests establish actual behavior; JSON Schema and manifest docs establish data contracts; workflows define packaging. The documentation must not widen inspection into installation, loading or device modification.

## Maintenance and review

- Keep the read-only boundary explicit in all device, package and security guides.
- Update this catalog and the relevant cluster hub when a page is added, moved or retired.
- Keep four README locales aligned on platform support, maturity, version, legal status and security limitations.
- Version JSON schemas and package manifests; explain breaking changes and migration paths.
- Distinguish candidate matching, file metadata, signature metadata, checksums and security verdicts.
- Verify relative links, commands and release claims before publication.
- Use the canonical [DAK documentation standard](https://github.com/Ivan-VHS/DAK/blob/main/docs/UNIFIED_DOCUMENTATION_STANDARD.md) for the shared 50-point README checklist.
