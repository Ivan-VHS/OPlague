# Tri-Color Duck UI — Design System

## 1. Визуальная идея

Tri-Color Duck UI — чистый инженерный интерфейс с образом белой утки, синим контуром и красным клювом. Утка — навигационная метафора и помощник диагностики, но не источник фиктивной телеметрии.

Правило распределения базовых цветов: примерно 65% светлые поверхности, 25% синий для структуры и активного состояния, 10% красный для ошибок/опасных действий. Доли ориентировочные.

## 2. Цветовые токены

| Token | Value | Использование |

| canvas-primary | #FFFFFF | основная рабочая поверхность |
| surface-porcelain | #F4F7FB | sidebar, панели, карточки |

| brand-cobalt | #0052CC | активная навигация, primary action |
| text-primary | #0A1F44 | основной текст |

## 3. Типографика и иконки

- UI: Segoe UI Variable на Windows; Inter как переносимая альтернатива.
- Технические ID, версии, hash и адреса: JetBrains Mono или системный моноширинный fallback.
- SVG grid: 24×24, базовая толщина 1.75 px.
- Иконка имеет синий/тёмный контур и один смысловой красный акцент.
- Не использовать цвет как единственное кодирование статуса: текст, форма или пиктограмма обязательны.

## 4. Сетка и геометрия

- Базовый шаг: 8 logical px.
- Минимальный размер окна: 1100×720 logical px.
- Верхний header: около 56–64 px.
- Sidebar: около 220 px.
- Inspector drawer: около 360 px.
- Радиус карточек: 12 px.
- Радиус интерактивных control: 6–8 px.
- Векторное масштабирование для HiDPI и 4K.

Размеры — исходные ориентиры; responsive режим адаптируется к меньшему размеру, а не обрезает контент.

## 5. Элементы

- Primary action: синий фон, белый текст.
- Secondary action: белый фон, синяя рамка и текст.
- Destructive action: белый фон, красная рамка; красная заливка — только при явном подтверждении/наведении.
- Status pill: OK, WARNING, ERROR, UNKNOWN и UNSUPPORTED имеют разные подписи и визуальные формы.
- Driver badge: SIGNED/VERIFIED, INVALID, UNKNOWN и UNSIGNED не объединяются в один статус.
- Таблицы: сортировка, поиск, фильтрация, закреплённый заголовок и видимый фокус.
- Inspector Drawer: паспорт узла, идентификаторы, драйвер, доказательства, события и доступные операции.

## 6. Duck Agent states

- Surface: спокойная утка, состояние соответствует фактическим данным.
- Scanning: ограниченная анимация сканирования.
- Finding: подсветка узла только после получения диагностики.
- Critical: красный alert с сообщением и временем события.
- Kernel Dive: экспертные представления доступны только при наличии данных провайдера.

Движение не должно изображать DPC/ISR без настоящего источника. Предусмотреть reduced-motion.

## 7. Доступность

- Клавиатурная навигация и логичный порядок Tab.
- Видимый focus ring толщиной около 2 px.
- Контраст текста минимум WCAG AA для обычного текста.
- Масштабирование UI и длинных идентификаторов.
- Локализация без захардкоженной ширины текста.
- Screen-reader labels на кнопках и интерактивных графах.
- Описание конфликтов словами, не только цветом.

## 8. Текущая реализация

Первый Slint экран использует базовую палитру, sidebar, dashboard, карточки, read-only summary и сканирование. Полный набор 180 SVG-иконок, анимация маскота, граф топологии, Inspector Drawer, tray и HiDPI QA остаются задачами roadmap.
